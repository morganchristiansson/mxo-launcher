# VTable `0x004b3df8` - type-2 connection-status work item

## Current best identity

This is the small queued `0x0c` work-item family used for worker-thread connect-status / result
submission.

High-confidence evidence:

- current Ghidra names:
  - `0x435030 = CLTThreadPerClientTCPEngine_ConnectionStatusWorkItem_ctor_zeroPayload`
  - `0x435050 = CLTThreadPerClientTCPEngine_ConnectionStatusWorkItem_ctor_withPayload`
  - `0x435c30 = CLTThreadPerClientTCPEngine_ConnectionStatusWorkItem_dtor`
  - `0x435d90 = CLTThreadPerClientTCPEngine_ConnectionStatusWorkItem_Allocate`
- ctor `0x435050`
  - writes `+0x00 = 0x004b3df8`
  - writes `+0x04 = 2`
  - writes caller-supplied payload/status dword to `+0x08`
- producer families in the arg5 connect / worker path use `0x435d90 -> 0x435050(payload)`
- the shared queue consumer and later connection leaf fallbacks treat it as work type `2`

## Layout

Like the shared `0x004b2134` root prefix, the concrete visible object is only `0x0c` bytes:

| Offset | Meaning |
|---|---|
| `+0x00` | vtable `0x004b3df8` |
| `+0x04` | work type `2` |
| `+0x08` | connect-status / payload dword |

## Runtime role

Current best read on the launcher auth/margin path:

- worker detects connect completion or connect failure
- allocates `0x0c` via `0x435d90`
- constructs via `0x435050(payload)`
- enqueues `(workItem, context=connection, queueSelect=0)`
- auth/margin leaf completion handlers consume the type-2 result through the normal
  `CMessageConnection` family callback path
