# 0x004b512c - CLTLoginState_State10

## Overview
Family B helper for the auth-reply handoff into the post-auth margin stage. Only 4 bytes wide in the dispatch table.

- `CLTLoginState_AuthReplyPending`

## Key specialized methods
- `0x004401a0` is one of the best anchored methods in the whole branch: it is the auth-reply handler that allocates the next state object, copies a string into owner-managed storage, then explicitly switches state to `0x0b` and posts event `0x14`.
- `0x0043bf90` is now re-read as a gated small packet-builder/send body:
  - first gate: `0x41b4b0`
    - owner `+0x1c` must be non-null
    - connection state field `+0x34` must equal `2`
    - otherwise original switches helper state to `4`
  - second gate:
    - owner byte `+0xf14` must be non-zero
    - otherwise original switches helper state to `6`
  - packet-builder family:
    - `0x43a1f0` initializes a tiny raw-`0x0a` packet object
    - `0x43aa80` copies owner `+0x108` into the packet's `CharacterName` field
  - then it sends through `0x41af70` and posts event `0x13`
- source ownership consequence:
  - the active scaffold now keeps that slot-3 body in
    `matrixstaging/game/src/libltclientlogin/loginstate.cpp`
    as `CLTLoginState_State10::Slot3_BeginOrContinue`
  - the local packet-builder family is source-owned there too as:
    - `0x43a1f0 = CLTLoginMediatorPacket0x0a_ResetAndInitialize`
    - `0x43aa80 = CLTLoginMediatorPacket0x0a_SetCharacterName`
  - mediator only keeps the narrow shared gates/transport helpers:
    - `0x41b4b0` connection-state check
    - `0x41af70` current-connection send helper
- Slot 7 (`0x00438ca0`) returns `10`, which matches the idea that this is the state immediately before the post-auth state `11` stage.

## Composition notes
- This is the clearest bridge into the post-auth subchain `0x004b512c -> 0x004b5154 -> 0x004b517c -> final leaves`.
- That makes it an important **intermediate pipeline node**, even though it is still a concrete dispatch-table entry rather than a synthetic root class.
