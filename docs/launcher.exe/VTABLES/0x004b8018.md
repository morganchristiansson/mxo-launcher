## Why this file was updated

A previous correction pass fixed the `0x449ca0` mislabel, but it also collapsed the old row listing too aggressively.
This file now keeps the correction **and** preserves the concrete row inventory again.

## Interpretation

This still looks like a transient abstract/shared root rather than a normal long-lived concrete class vtable.
But the exact slot taxonomy is still only partly recovered.

What is safe to say now:

- this table participates in shared connection initialization
- it contains a mix of:
  - destructor / deletion helpers
  - at least one real shared connection wrapper (`0x449ca0`)
  - several purecall-backed abstract/unimplemented rows
  - one tiny `return true` stub row at `0x437860`
- the concrete path quickly transitions to `0x004b8034`
