## Key specialized methods
- `0x004393f0` is strong evidence that slot 2 is genuinely virtual here: it explicitly falls back to the shared `0x00438df0`, but on its special case it calls `(*(this->vtable)[2])(this+4)`.
- `0x00439300` uses the cached object's state code to choose which margin connection path to start; cases `6`, `7`, `8`, `0x0d`, and `10` all take distinct connection paths.
- Slot 7 (`0x004686b0`) returns `4`, so this object appears to correspond to state `4`.

## Composition notes
- This is one of the clearest **derived override** cases in Family B because slot 2 explicitly falls back to the shared base implementation when its own special case does not apply.
- Together with `0x004b5064` and `0x004b50dc`, it defines the B1 sub-branch that customizes slot 2 instead of keeping `0x00438df0` unchanged.
