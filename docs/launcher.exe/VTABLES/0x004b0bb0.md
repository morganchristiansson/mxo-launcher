# 0x004b0bb0 - CLTLoginState_State16

## Overview
Family A leaf focused on PIN workflow execution plus success logging. This helper is only 4 bytes wide, so it does not cache an upstream pointer.

## Key specialized methods
- `0x00420720` is the main specialized method here: it gates on mediator connectivity, validates a PIN buffer at offsets `+0x60` / `+0x64`, and only then calls the outbound routine at `0x00488310`.
- `0x004207c0` contains the strongest anchored text in this Family A branch because it prints `"LaunchPad login successful."` before switching state `1`.
- Slot 7 (`0x00420320`) returns `0x10`, matching this helper's fixed mediator-state identity.
- Newer `0x41ecd0` review now also makes state `16` a concrete **alternate password-submit target** on the non-default branch:
  - when the observed happy-path static instead has `g_LaunchPadGateState16State18 != 0`,
    `ProcessLoginRequest` can switch to helper/state `16`
  - replacement source now keeps that state16/state18 family as a default-off scaffold so future
    non-happy/session work can be tightened without disturbing the live existing-character route
  - keep that separate from the earlier startup `0x406470` gate use, which instead calls owner
    vtable `+0x140` (`station_login` side effect)

## Composition notes
- This still looks like a concrete **login-state object**, not a shared base class.
- Compared with `0x004b0b88` and `0x004b0c00`, this leaf is less about caching local state and more about running the outbound PIN workflow immediately.
