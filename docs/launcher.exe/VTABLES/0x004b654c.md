# Local margin packet-builder cluster around `0x004b654c`

This doc reuses the historical filename `0x004b654c.md`, but the important current read is the
**whole contiguous packet-builder cluster** rooted at:
- `0x004b6524`
- `0x004b6538`
- `0x004b654c`
- `0x004b6560`
- `0x004b6574`

These are the local margin-side builders used by the consumed base-margin send branches around:
- `0x441f30`
- `0x4429b0`

## Shared raw layout

All five tables in this cluster sit on the same local helper shape:
- base envelope front matter from `0x439840`
  - `+0x00` = local builder vtable
  - `+0x04` = cached payload base
  - `+0x08` = retained live outer message-ref
- derived helper fields
  - `+0x0c` = helper-local byte/flag on the active builders here
  - `+0x10` = packet payload base used by the fixed-field writers
- some families then add a trailing reservation sidecar at `+0x14/+0x18`

Shared rows across this cluster:

| Offset | Target | Current best read |
|---:|---:|---|
| `+0x00` | `0x00443aa0` | local dtor / release retained outer message-ref |
| `+0x04` | `0x00437b50` | tiny stub |

| `+0x0c` | builder-specific | reset/init helper |
| `+0x10` | `0x00481760` | return builder `+0x10` packet-payload base |

## Practical current consequence

The important margin send-path correction is that the active consumed branches are no longer best
read as "bare message-ref + copied bytes" send helpers.
They now narrow to real local builder families:
- `0x441f30` -> vtable `0x004b6524`
- `0x4429b0` -> vtable `0x004b6560`

That means the active source mirror should keep explicit:
- local builder vtable selection
- packet payload base `+0x10`
- reservation side fields where present
- final forwarding through `0x41cf30 -> 0x448cf0`
