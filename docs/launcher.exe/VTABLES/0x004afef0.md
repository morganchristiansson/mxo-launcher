# VTable 0x004afef0 - older note named `CBasicMarginConnection`

## Correction note

A newer focused startup pass shows that `launcher.exe:0x41d170` allocates a `0xa8` connection
child, overwrites its vtable to `0x004afef0`, stores owner at `+0xa4`, configures packet-name
callback `0x41ce00`, and then immediately calls `connection->+0x1c(owner+0x5c)` on the **auth**
startup path.

So, within the current receive/queue focus area, treat `0x004afef0` primarily as the
**auth-side startup leaf wrapper** around base `0x4490c0`, even though older wider class notes here
still use the `CBasicMarginConnection` name.

## Current bounded receive-tail correction

A newer post-copy receive pass now makes one later auth-side destination concrete enough to source-own
without claiming the whole `0x4490c0` message-object tail.

Static-RE-backed chain on the auth startup leaf:
- queue type `3`
- base `0x4490c0` copies parsed packet bytes
- local receive/message-ref scaffold mirroring `0x455cd0 -> 0x455c60`
  - outer ref `+0x0c` = inner message storage
  - outer ref `+0x10` = headerless flag
- copied spans append into that inner storage through the nearer `0x4557b0`-style grow step
- original headerless locator-id validity gate
- leaf dispatch `0x449a30`
- local base-filter mirror of `0x442d00`
- owner `+0x180 / 0x41f250`
- current helper slot `+0x10` / slot 5 (`AuthMessageDispatch`)

Current source consequence:
- handled auth copied packets no longer jump straight from raw copied bytes into the mediator-owned
  staging wrapper
- source now keeps the next safer original step local to the auth leaf first:
  - construct the nearer outer-ref/inner-storage receive object
  - reject invalid headerless locator ids there
  - read later message codes through the same `0x41bc20/0x41bbb0`-style object seam
  - apply the same narrow consumed-code `2/4/5` filter shape before owner `+0x180`
- the surviving branch then re-enters the nearer helper-slot-5 path directly from the connection
  callback
- the later synthetic auth receive-drain proxy therefore remains pushed toward a fallback/no-op
  role on that handled auth branch instead of remaining the only live consumer after the copy step
