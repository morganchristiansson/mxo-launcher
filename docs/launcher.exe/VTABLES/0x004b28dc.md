# 0x004b28dc - CLTThreadPerClientTCPEngine::WorkerThread

## Overview

`0x004b28dc` is the derived thread vtable for the engine's per-connection worker thread object.

Current evidence:

- `startup_objects/0x4d6304_network_engine.md` already narrowed the `+0x8c` tree payloads to **WorkerThread-style** objects
- the derived vtable keeps the generic `CLTThread` base surface from `0x004b2850`
- its slot `+0x20` override is now named `CLTThreadPerClientTCPEngine_WorkerThread_Run`
- its deleting dtor is `0x00431be0 = CLTThreadPerClientTCPEngine_WorkerThread_deleting_dtor`

This object owns the main socket worker loop for a single connection/context pair.

## Relationship to the generic thread base

Like the accept-thread and queue-thread objects, this vtable inherits most slots unchanged from:

- `0x004b2850`

The important override is again the thread-main slot:

- base slot `+0x20` placeholder
- overridden here by `0x0042fe50 = CLTThreadPerClientTCPEngine_WorkerThread_Run`

## Key specialized methods

### `0x0042fe50 = CLTThreadPerClientTCPEngine_WorkerThread_Run`

High-confidence behavior from exact log strings and decompilation:

- drives the connect-completion path for outbound workers
- transitions the owning connection state to connected / closed / failed states as needed
- handles recv loops for both TCP-style and datagram-style connection objects
- handles send progress and partial-send retry bookkeeping
- logs socket errors, zero-byte receive, wakeup-socket wakeups, explicit exit-by-request, and select/recv/send failures
- enqueues the appropriate completed-operation objects back to the engine on connect success, connect failure, closure, and error paths

### `0x00431be0 = CLTThreadPerClientTCPEngine_WorkerThread_deleting_dtor`

This wrapper:

- tears down the worker-thread wakeup helper at `this + 0x40`
  - newer socket-layer pass now tightens that helper to raw-socket lifecycle calls:
    - `0x452300 = CLTSocketLayer_DeleteWakeupSocketHandle`
    - paired setup in the ctor uses `0x452270 = CLTSocketLayer_InitConnectedLoopbackWakeupSocketHandle`
  - important negative result: this `+0x40` wakeup helper is **not** currently a vtable-backed subobject
- tails into `CLTThread_dtor`
- returns the memory block to the engine's local free-list when bit 0 of the destructor flag is set
