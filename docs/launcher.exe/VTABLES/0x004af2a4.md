# VTable `0x004af2a4` - base local packet-builder envelope helper

This is the small shared stack-local packet-builder base used by the margin/auth senders that go
through:
- `0x439840 = CLTLoginMediatorPacketBuilderEnvelope_Initialize`
- `0x41af70 -> 0x41cf30 -> 0x448cf0`

It is **not** the outer message-ref object itself.
Instead it is the tiny local helper that retains one live outer message-ref from the
`0x004ba23c` family and exposes the first raw payload pointer for later builder-specific writes.

## Current source mapping

Canonical source home:
- `matrixstaging/game/src/libltclientlogin/loginstate_packet_builder_scaffold.h`
- `matrixstaging/runtime/src/libltmessaging/messageconnection.h`

Current best conceptual mapping:
- `CMessageConnectionPacketBuilderEnvelope`
- `CMessageConnectionPacketBuilderPayloadScaffold`
- builder-specific raw reservation sidecars on top of those

## Base raw layout

Recovered from `0x439840`:
- `+0x00` = vtable `0x004af2a4`
- `+0x04` = cached payload base = `messageRef+0x0c -> inner+0x0c`
- `+0x08` = retained live outer message-ref object (`0x004ba23c` family)

`0x439840` does:
1. install base vtable `0x004af2a4`
2. create a live outer message-ref through `0x455cd0 -> 0x455c60`
3. retain/store that object at local `+0x08`
4. cache inner payload base at local `+0x04`

## Important derived-layout follow-up

The active senders do not stop at the base `+0x00/+0x04/+0x08` front matter.
After `0x439840`, several builder families immediately retable the local object and expose a common
next pointer at raw `+0x10`:

- common derived follow-up on the active family:
  - `+0x0c` = helper-local byte/flag cleared by reset/init helpers
  - `+0x10` = packet payload base used by fixed-field writers and reservation helpers
- repeated reservation sidecar shape used by `0x43a230 / 0x43acf0`:
  - `+0x14/+0x1c/+0x24/+0x2c ...`
  - each triplet is:
    - pointer to the concrete write span immediately after the little-endian reserved-length word
    - reserved content byte count (`u16`)

That is now the key correction over the older “front matter only” read.

## Shared virtual rows

Current best row read across this local builder family:

| Offset | Target | Current best read |
|---:|---:|---|
| `+0x00` | `0x00443aa0` | local dtor / release retained outer message-ref |
| `+0x04` | `0x00437b50` | tiny stub / returns `0` on the current builder families |
| `+0x08` | builder-specific | append debug string |
| `+0x0c` | builder-specific | reset/init helper |
| `+0x10` | `0x00481760` on active derived families | return builder `+0x10` packet-payload base |

That `+0x10` getter matters directly for `0x43a230 / 0x43acf0`, which compute stored string/blob
offsets relative to the packet payload base, not relative to the raw envelope cache at `+0x04`.

## Why this doc matters

This base envelope is the seam between:
- launcher/game-side stack-local packet construction
- the live outer message-ref object family (`0x004ba23c`)
- the shared inherited send path at `0x41cf30 -> 0x448cf0`

The important correction is that the active builders now have enough recovered structure to track:
- exact local vtable selection
- packet payload base `+0x10`
- reservation side fields used before the envelope is forwarded
