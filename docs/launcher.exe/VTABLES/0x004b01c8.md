Focused startup-path note:
- vtable slot `0x004b01cc -> 0x0041b160` (`CLTLoginMediator_Initialize`) now has a clearer current read:
  - parameter `networkEngineOverride`

- that aligns this initializer directly with the same `CLTThreadPerClientTCPEngine` object built at launcher helper `0x40a380`
- newer post-auth/state-8 review now also makes the following owner-vtable family much more concrete:
  - `+0x40 / 0x41f2e0` = current character-slot record table accessor over owner `+0x688`
  - `+0x44` = inline thunk using owner byte `+0xcc8` to read that same current character-slot entry
  - `+0xe0 / 0x41b260` = state-8 margin-route string getter over owner `+0x818`

  - `+0xfc/+0x100/+0x104/+0x108` = world-descriptor readers over owner `+0xd84`
- broader writer `0x43f300 = CLTLoginState_AuthenticatePending_AuthMessageDispatch` now gives the key relation between them:
  - `+0xd84` is the world-descriptor table
  - `+0x688` is the character-slot table
  - `+0x818` is seeded by matching character world-id against the world-descriptor table and copying the descriptor name
- together these now look like a real post-auth character/world/route interface family rather than unrelated tiny helpers
