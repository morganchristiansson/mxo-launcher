# 0x004b2880 - CLTThreadPerClientTCPEngine::AcceptThread

## Overview

`0x004b2880` is the derived thread vtable for the engine's accept-thread worker object.

Current evidence:

- `startup_objects/0x4d6304_network_engine.md` already narrowed the `+0x80` tree payloads to **AcceptThread-style** objects
- the derived vtable keeps the generic `CLTThread` base surface from `0x004b2850`
- its slot `+0x20` override is now named `CLTThreadPerClientTCPEngine_AcceptThread_Run`
- its deleting dtor is `0x00431b30 = CLTThreadPerClientTCPEngine_AcceptThread_deleting_dtor`

This object waits on the listening socket / wakeup socket pair, accepts incoming connections, and spins up WorkerThread-backed connection objects for accepted clients.

## Relationship to the generic thread base

Like the queue-thread and worker-thread objects, this vtable inherits most slots unchanged from the shared thread-base vtable at:

- `0x004b2850`

The important per-class override is the thread-main slot:

- base slot `+0x20` placeholder
- overridden here by `0x00432070 = CLTThreadPerClientTCPEngine_AcceptThread_Run`

## Key specialized methods

### `0x00432070 = CLTThreadPerClientTCPEngine_AcceptThread_Run`

High-confidence behavior from exact log strings and decompilation:

- waits on the listening socket and wakeup socket
- calls `accept()` on incoming TCP clients
- logs both rejected and accepted connections
- asks the engine object whether the client should be accepted
- on success:
  - creates a connection / worker object for the accepted socket
  - stores the peer address on that connection
  - marks the connection state as `2`
  - creates a `CLTThreadPerClientTCPEngine::WorkerThread` object
  - inserts it into the engine's context-keyed worker tree
  - enqueues the corresponding completed-operation item

### `0x00431b30 = CLTThreadPerClientTCPEngine_AcceptThread_deleting_dtor`

This wrapper:

- tears down the accept-thread wakeup helper at `this + 0x40`
- tails into `CLTThread_dtor`
- frees `this` when bit 0 of the destructor flag is set
