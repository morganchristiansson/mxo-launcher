# 0x004b5014 - CLTLoginState_AuthenticatePending

## Overview
Family B state object for an earlier auth/bootstrap stage. The object is 8 bytes wide because it caches an upstream pointer at `this+4`.

## Key specialized methods
- `0x00439210` clearly belongs to the mediator bootstrap path:
  - if auth is **not** connected yet, it switches back to helper/state `1`
  - if auth **is** connected, it gathers mediator data and calls `AuthBootstrap680_PrepareAndDispatch(...)`
- `0x0043f300` is one of the largest methods in this whole family; it parses auth results, builds owner-managed world/character arrays, normalizes invalid status/type values, and posts events `5` / `6` or errors depending on the return code.
- Slot 7 (`0x00418150`) is a tiny getter returning `2`, which fits the idea that this helper is an early auth-side state.

## Practical state-flow note
On the current startup path this looks less like “the very first auth state” and more like the
**post-submit bootstrap coordinator**:
- mediator init installs state `0` as the initial current helper
- password submit (`0x41ecd0`) switches to helper/state `2`
- helper/state `2` then either:
  - bounces to state `1` to start the auth transport connection, or
  - continues directly into bootstrap dispatch when auth is already in ready state `2`

## Composition notes
- This is best described as an **auth/bootstrap login-state object**.
- Compared with `0x004b4fec`, it sits earlier in the pipeline and performs much heavier bootstrap-side materialization work.
