# VTable `0x004c05d0` - inline `0x80`-byte storage leaf on the `0x004c0540` base

## Current best read

This is a fixed-size inline byte-storage leaf in the `0x004c0540` family.

Construction and use from `0x4830f0` prove:
- object allocation size = `0x90`
- inline payload begins at `+0x0c`
- stored byte-count dword lives at `+0x8c`
- inline capacity = `0x80` bytes

## Producer proof

`0x4830f0` selects this leaf when `totalBytes <= 0x80`.
It:
- allocates `0x90`
- sets `refcount04 = 1`
- zeroes `+0x08`
- installs vtable `0x004c05d0`
- stores `totalBytes` at `+0x8c`
- copies the first span, then second span, into the inline buffer returned by vtable `+0x10`

## Destructor behavior

`0x4833d0` just retables back to the abstract base `0x004c0540` and optionally frees the object.
There is no extra heap-buffer teardown here because storage is inline.
