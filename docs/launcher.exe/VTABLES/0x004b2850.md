# 0x004b2850 - generic `CLTThread`-style base vtable

Current best reading:
- `0x004b2850` is the shared **generic thread-base vtable** installed by `0x4319e0` / `CLTThread_ctor`
- the base-class name is still **provisional**
  - there is no direct recovered class-name string for the base itself yet
  - current `CLTThread_*` names are shorthand chosen because this vtable is shared by several launcher thread objects and is anchored by `pcthread.cpp` logging at runtime helpers like `_StartAddress_00452800` / `CLTThread_LogExit`
- this base is reused by at least:
  - `CLTThreadPerClientTCPEngine_QueueThread`
  - `CLTThreadPerClientTCPEngine::AcceptThread`
  - `CLTThreadPerClientTCPEngine::WorkerThread`
  - `CRezMgr_PreFetch_Loader_Thread`

## Relationship to `0x004b3e28`

`0x004b3e28` is the queue-thread derived vtable built on top of this base.

High-confidence relation:
- `0x4365a0` / `CLTThreadPerClientTCPEngine_QueueThread_ctor`
  - first calls `0x4319e0` / `CLTThread_ctor`
  - that base ctor installs this vtable at child `+0x00`
  - then the queue-thread ctor overwrites the vtable with `0x004b3e28`
- the queue-thread vtable keeps the inherited base implementations for start / stop / wait / suspend / current-thread checks / exit logging / deleting dtor
- its important queue-thread-specific override is slot `+0x20`, where the base placeholder is replaced by the real queue consumer entrypoint `0x436fc0` / `CLTThreadPerClientTCPEngine_QueueThread_Run`

## Thread entry sequencing

Worker `_StartAddress_00452800` shows how the virtuals are used:

1. slot `+0x00` -> fetch thread-name string object
2. slot `+0x24` -> pre-run hook
3. slot `+0x20` -> thread main / body
4. slot `+0x28` -> exit-log hook

That is why slot `+0x20` is the key derived override across these thread classes.

## Slot map

| Offset | Function | Current name | Current meaning |
|---|---:|---|---|
| `+0x00` | `0x4319d0` | `CLTThread_GetNameString` | returns `this + 4`, the internal string object used by thread-start / exit logging |
| `+0x04` | `0x4528d0` | `CLTThread_Start` | begins with a virtual self-dispatch through slot `+0x10` / `IsRunning()`; if already running returns `0x8000005`, otherwise starts `_beginthreadex(..., CREATE_SUSPENDED, this)`, sets priority, and resumes; returns `0` on success, `1` on creation/resume failure |
| `+0x08` | `0x4525d0` | `CLTThread_Resume` | lock-protected resume helper; if called from the current thread it increments nested counter `+0x2c`, otherwise it calls `ResumeThread(handle)` |
| `+0x0c` | `0x452660` | `CLTThread_Stop` | self-call path exits the current thread; external path acquires the thread lock, then virtual self-dispatches through slot `+0x10` / `IsRunning()`, force-terminates via `TerminateThread(handle, 0)`, and optionally waits |
| `+0x10` | `0x431a60` | `CLTThread_IsRunning` | `handle != NULL && WaitForSingleObject(handle, 0) == WAIT_TIMEOUT` |
| `+0x14` | `0x4526e0` | `CLTThread_Wait` | `WaitForSingleObject(handle, INFINITE)` |
| `+0x18` | `0x452620` | `CLTThread_Suspend` | lock-protected suspend helper; decrements nested counter `+0x2c` when positive, otherwise calls `SuspendThread(handle)` |
| `+0x1c` | `0x431a40` | `CLTThread_IsCurrentThread` | compares stored thread id `+0x34` against `GetCurrentThreadId()` |
| `+0x20` | `0x48bc34` | import-thunk / abstract placeholder | base thread-main slot; concrete derived thread classes overwrite this with their real body function |
| `+0x24` | `0x437b50` | `CLTThread_NoOp` | no-op pre-run hook; returns `0` |
| `+0x28` | `0x452770` | `CLTThread_LogExit` | logs `"%s exiting.\n"` using the thread-name string |
| `+0x2c` | `0x431a80` | `CLTThread_deleting_dtor` | deleting-dtor wrapper over `CLTThread_dtor`, freeing memory when bit 0 of the flag is set |

## Construction / destruction anchors

### Base ctor
- `0x4319e0` / `CLTThread_ctor`
- seeds the name-string storage at `+0x04..+0x0c`
- initializes the lock helper at `+0x10 / +0x14`
- zeroes:
  - `+0x2c`
  - `+0x30` thread handle
  - `+0x34` thread id
- installs this vtable before derived ctors replace it

### Base dtor
- `0x452950` / `CLTThread_dtor`
- restores this base vtable
- closes thread handle at `+0x30`
- deletes the critical section at `+0x14`
- frees the thread-name string at `+0x04..+0x0c`

### Derived override examples
- `0x004b3e28` queue thread -> slot `+0x20 = 0x436fc0`
- `0x004b2880` accept thread -> slot `+0x20 = 0x432070 = CLTThreadPerClientTCPEngine_AcceptThread_Run`
- `0x004b28dc` worker thread -> slot `+0x20 = 0x42fe50 = CLTThreadPerClientTCPEngine_WorkerThread_Run`
- `0x004bcbd0` prefetch loader thread -> slot `+0x20 = 0x479270`

## Current confidence

High confidence:
- this is the common thread-base vtable beneath several launcher worker-thread classes
- start / stop / wait / suspend / current-thread / log-exit semantics above are directly backed by current decompile + disassembly
- slot `+0x20` is the derived thread-main slot used by `_StartAddress_00452800`

Lower confidence:
- the exact original source class name of this generic base is still not string-backed yet
- so the `CLTThread_*` naming is still a practical, evidence-backed shorthand rather than final original-source proof
