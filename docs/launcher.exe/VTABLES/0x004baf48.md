# 0x004baf48 - agenda read/write helper table in the broader `CStreamPacketEncryptionModule`-related family

## Current best read
This table is now a clearly related helper-family table, not an isolated one-off:
- it shares the same leading destructor/delete helper pair as base helper table `0x004b81c8`
- original agenda initializer `0x469850` installs this same vtable twice:
  - agenda `+0x0c` labeled `"Agenda read helper"`
  - agenda `+0x28` labeled `"Agenda write helper"`

Recovered behavior:
- slot `+0x00` (`0x44c680`) = tiny base/helper dtor
- slot `+0x04` (`0x44bb60`) = delete-if-nonnull-style helper
- slot `+0x08` (`0x481750`) = returns helper field `+0x0c`
  - on the embedded agenda helpers that is the label string:
    - `"Agenda read helper"`
    - `"Agenda write helper"`
- slot `+0x0c` (`0x469980`, now `CMessageConnectionPacketAgendaHelper_StoreOpaqueMessageRef`) = stores/replaces a refcounted object pointer through helper field `+0x10`
- slot `+0x10` (`0x469720`, now `CMessageConnectionPacketAgendaHelper_DelegateToChainedHelper`) = if helper field `+0x14` is live, delegates into that object's
  vtable `+0x10`

Tighter agenda-fit from `0x469850 = CMessageConnectionPacketAgenda_ctor` /
`0x469740 = CMessageConnectionPacketAgenda_InstallStreamPacketEncryptionModule`:
- `0x469850` initializes agenda `+0x00` with the owning `CMessageConnection*`
- the embedded read helper at agenda `+0x0c` is configured as:
  - label at helper `+0x0c` = `"Agenda read helper"`
  - output slot pointer at helper `+0x10` = `&agenda+0x08`
  - downstream-helper-slot pointer at helper `+0x14` = `&agenda+0x44`
- the embedded write helper at agenda `+0x28` is configured as:
  - label at helper `+0x0c` = `"Agenda write helper"`
  - output slot pointer at helper `+0x10` = `&agenda+0x24`
  - downstream-helper-slot pointer at helper `+0x14` = `NULL`
- agenda `+0x40` initially points at the embedded read helper at `+0x0c`
  - `0x469930`, now `CMessageConnectionPacketAgenda_DispatchReadHelperChain`, simply drives that
    helper chain and returns agenda `+0x08`
- agenda `+0x44/+0x48` are the write-helper head/tail pointers
  - `0x469950`, now `CMessageConnectionPacketAgenda_DispatchWriteHelperChain`, drives the write
    chain when `+0x44` is non-null and otherwise returns the original input message-ref untouched
- when a `CStreamPacketEncryptionModule` is installed:
  - module read helper `0x004b86f0` becomes the read-chain head at agenda `+0x40`
  - module write helper `0x004b8690` is appended onto agenda `+0x44/+0x48`
  - module owner `+0x10` receives agenda `+0x00` (the owning connection pointer)
  - both chain back into these embedded `0x004baf48` helpers

So current best structure read is:
- `0x004b81c8` = common helper base
- `0x004baf48` = concrete agenda helper table used for both embedded read/write helper objects
