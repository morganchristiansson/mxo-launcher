# 0x004add70 - LogRouterFileSinkLock

## Overview

`0x004add70` is the tiny vtable used by each per-file-sink lock object embedded inside `LogRouter`.

Current evidence:

- `LogRouter_Construct` (`0x414a70`) stores this vtable into five embedded lock objects
- each lock object then gets a `CRITICAL_SECTION` initialized immediately after the vtable pointer
- `LogRouter_OpenFileSink`, `LogRouter_CloseFileSink`, and `LogRouter_WriteBufferToFileSink` use these lock objects to serialize file-sink access

This is an internal helper vtable, but it matters for long-term readability because it explains the `0x11c .. 0x1a7` region inside `LogRouter`.

| Offset | Current read | Notes |

The object size implied by the surrounding `LogRouter` layout is `0x1c` bytes.

## Related helper

Not a vtable entry, but directly associated with this tiny class:

- `0x00414790` `LogRouterFileSinkLock_Destruct`
  - restores vtable `0x004add70`
  - calls `DeleteCriticalSection(this + 4)`

## Important boundary after the vtable

The vtable is only **two slots** long.
Data immediately after it is not more methods:

- `0x004add78` -> `"w"`
- `0x004add7c` -> `"a"`
- `0x004add80` -> start of the `LogRouter` vtable

Those adjacent strings are used by `LogRouter_OpenFileSink` when choosing `_fsopen` mode.
