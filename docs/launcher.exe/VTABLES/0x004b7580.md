## Important current boundary
The validator inner-worker family is now closed tightly enough for a faithful source-side
implementation of the active finalize path:
- temp worker allocation/layout is bounded well enough to name and mirror

Current live fallback-key runs now pass both:

- child `+0xac` auth-reply-copy validation

Latest runtime evidence also no longer emits the earlier diagnostic rejection warnings for either
validator path.

So the old diagnostic-only bypasses are no longer needed for the active path.

Remaining uncertainty is narrower now and mainly outside the enforced finalize behavior:
- exact `qspubkey.dat` file-reader framing/object stack

## What `0x468520` now appears to do
Current best read:
- it does **not** just copy signature bytes into the worker
- it uses the outer validator's RSA/public-key helper family at `this+8`
- it materializes the signature as a big-int
- it applies the outer RSA public operation to that signature value
- it encodes the resulting representative bytes into the worker `+0x18` buffer of length `+0x14`

So this stage now looks like:
- signature input -> RSA public transform -> encoded representative bytes stored on temp worker

not merely:
- signature input -> raw byte copy

## What `0x467ee0 / 0x467f70` now do
- both consume the supplied temp worker
- both fetch the worker-local digest object through worker vtable `+0x44`
- both consult the outer compare-context family returned from the validator helper at `this+8`
- `0x467ee0` is the bool/finalize path used by outer slot `+0x28`
  - it calls compare-context `+0x18 = 0x4680a0`

- `0x467f70` is the two-dword result-pair helper used by outer slot `+0x34`
  - current active-path significance remains low; the surrounding compare-context pair helpers are

## Current source-side implementation
The current source implementation now mirrors the recovered active finalize behavior directly:
- temp worker hashes its fed bytes through MD5
- finalize builds the exact EMSA-PKCS1-v1_5(MD5) encoded block using the recovered 18-byte MD5
  `DigestInfo` prefix
- that block is compared byte-for-byte against the RSA-decoded representative stored on the temp
  worker

This replaced the older bounded “raw PKCS#1 tail equals caller bytes” hypothesis and is now
strong enough to enforce the validator on the live active path.
