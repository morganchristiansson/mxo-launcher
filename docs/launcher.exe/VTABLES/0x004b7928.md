## Class Identification

**This vtable represents a specialized CMessageConnection subclass** with unique cleanup requirements different from CBaseMarginConnection.

### Evidence:
- Contains **FUN_00449090** (14 instructions) - State check helper
- Contains **FUN_004490c0** (792 instructions) - **CMessageConnection::OnOperationCompleted**
- Contains **FUN_00448cf0** (316 instructions) - **CMessageConnection::SendPacket**
- Inherits base CLTTCPConnection methods

## Purpose
**CAuthConnection** handles TCP messaging with different cleanup/initialization requirements than CBaseMarginConnection:
1. **State check**: FUN_00449090 performs state validation before operations
2. **Send packets**: `CMessageConnection::SendPacket` for outbound messages
3. **Receive data**: Inherited `CLTTCPConnection::OnReceive` for incoming data
4. **Complete operations**: `FUN_004490c0` processes completed operations
5. **Cleanup**: FUN_00448c30 performs cleanup (sets vtable to 0x004b7928, handles multiple memory regions)

## Usage

**CAuthConnection** is a concrete subclass of CMessageConnection used for authentication connections. Like all connection types, it inherits from CBaseConnection (0x004b8018) abstract root but immediately transitions to its concrete vtable during construction.

### Creation Contexts:
- **Created by**: `FUN_00449090` initialization routine (state validation)
- **Used by**: All connection types inherit from CBaseConnection abstract root (0x004b8018)
- **Purpose**: Standard connection type with state validation before operations

### Protocol Support:
- **Standard TCP protocol**: Supports basic CERT and MS messaging
- **State validation**: `FUN_00449090` performs state check before operations

### Key specialized methods:
- **FUN_00449090**: State check/helper - validates connection state before operations
- **FUN_004490c0 (CMessageConnection::OnOperationCompleted)**: Main operation completion handler (792 instructions, 105 complexity)
- **FUN_00448cf0 (CMessageConnection::SendPacket)**: Send messages with validation (316 instructions, 45 complexity)

## Current narrowed `0x4490c0` type-3 parsed-packet copy path

A newer focused pass over `CMessageConnection::OnOperationCompleted` now makes the first useful
consumer-side step more concrete than the older generic “operation completed” summary.

Static-RE-backed points from `0x4490c0`:

- `workItem+0x04` is the first dispatch key
- type `3` is the parsed-packet path fed from `CLTTCPConnection::OnReceive -> 0x436820`
- on that path, `0x4490c0` reads:
  - `CParsedPacketWorkItem.currentCursor24`
  - `CParsedPacketWorkItem.assembledByteCount28`
- the first copy span is computed from the first retained fragment and `currentCursor24`
- later spans walk subsequent retained fragments until the assembled packet-body byte count is
  satisfied
- if extra retained buffers remain after the requested body bytes were copied, the function reaches
  the string-backed:
  - `Unused buffers were attached to CLTTCPReadOperation from %d.%d.%d.%d:%d.`
- if `assembledByteCount28 > 0x1000`, the function logs the illegal packet and closes the
  connection before later dispatch work

## Relationship to CBaseConnection (0x004b8018)

**CBaseConnection is the abstract root of the connection hierarchy**. The relationship:

- **FUN_0044a9f0 constructor**: Creates objects with CBaseConnection's vtable (0x004b8018) as part of abstract base class pattern
- **Immediate transition**: FUN_0044aad0 immediately replaces vtable with concrete subclass vtable (CAuthConnection, CMessageConnection, etc.)
- **Abstract interface**: Slots 4-6 contain pure virtual methods that define the contract for all derived classes
- **Common initialization**: All connection types share common initialization in CBaseConnection before specializing

This is a classic C++ abstract base class pattern where objects are created with the abstract vtable but immediately transition to concrete subclasses.
