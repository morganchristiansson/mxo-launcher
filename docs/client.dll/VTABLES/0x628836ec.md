### `ClientShell_LoginMediatorObserver_OnEvent`
Current bounded behavior:
- handles at least events:
  - `0x0b`
  - `0x16`
  - `0x18`
- event `0x0b` reaches the cfg-save family
- event `0x0b` also pushes visible text `"Waiting for Regionserver"`
- event `0x18` first checks object byte `this+0xcc`, then:
  - calls mediator `+0x10c`
  - copies that small-string through `0x62009eb0`
  - calls `0x621c6d90`, which is the immediate event-`0x18` `+0x118` consumer
  - then calls the current object's transition helpers now renamed in Ghidra as:
    - `ClientShell_LoginMediatorObserver_PrepareTransition` (`0x62130700`)
    - `ClientShell_LoginMediatorObserver_AdvanceState` (`0x621704a0`)
- newest static+runtime explanation for the missing second observer on the working route:
  - event `0x0b` reads mediator `+0xc0` and copies byte `returnedBlock+0x464` into
    `DAT_629e689d`
  - latest successful replacement run logged that source byte as `0x01`
  - `ClientShell_LoginMediatorObserver_AdvanceState` state-0 branch immediately checks
    `DAT_629e689d != 0` and, when true, skips the later `ClientViewFactory_GetOrCreateViewById(0x67)`
    path that would have reached `LoadingAreaCommonLayoutView_ctor`
- newest successful replacement caller logging now proves the active route really does hit:
  - mediator `+0x10c` from return site `0x6217082b`
  - mediator `+0x118` from `0x621c6db3` inside `0x621c6d90`
  - that `+0x118` list now contains 17 entries on the successful run
- that same successful run still did **not** show a later `+0x118` call from `0x62017150` or a
  later second observer registration, so the current working route appears to stop after the
  immediate event-`0x18` helper rather than taking every later original-looking branch
- the older launcher-owned event-`0x0b` text mirror was removed because it was not an exact client-visible source
- a newer diagnostic-only opt-in hook at `client.dll:0x6215b930 = FUN_6215b930` logs the exact client-visible `"Waiting for Regionserver"` text when `MXO_DIAGNOSTIC_HOOK_CLIENT_LOADING_TEXT=1`
- that same hook can also replace the visible client string when `MXO_DIAGNOSTIC_OVERRIDE_CLIENT_LOADING_TEXT=1`; default behavior still avoids client-memory patching
